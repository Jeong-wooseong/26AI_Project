# 분류 정확도 평가

## 데이터

| 파일 | 내용 | 용도 |
| --- | --- | --- |
| `sample_reviews_v1.csv` | 직접 작성한 개발용 예시 리뷰 50개 (칭찬 14, 불만 14, 악성 6, 문의 8, 평점만 8) | 프롬프트 개선(튜닝)용 |
| (5주차에 추가) | 실제/공개 리뷰 50개를 수집해 직접 라벨링 | **최종 정확도 측정용** |

- 열: `id, rating, content, label, note`
- `label`: `PRAISE`(칭찬) / `COMPLAINT`(불만) / `MALICIOUS`(악성) / `INQUIRY`(문의) / `RATING_ONLY`(평점만)
- 개발용 셋에는 판단이 갈리는 경우를 일부러 넣었다: 칭찬+불만 섞임, 별점과 본문이 어긋남, 칭찬+질문, 물음표 없는 질문, 협박성 리뷰. 개인정보 마스킹 확인용 리뷰(전화번호, 동·호수, 이메일)도 포함한다.
- 같은 셋으로 프롬프트를 고치고 최종 점수까지 내면 점수가 부풀려지므로, 최종 측정은 이 셋에 없던 리뷰로 한다.

## 라벨 기준 (`backend/src/main/resources/prompts/classify_v1.txt` 와 동일)

1. 불만이면서 욕설·비방·협박이 있으면 **악성**. 강한 불만이나 낮은 별점만으로는 악성이 아니다.
2. 칭찬과 질문이 섞여 있고 답해야 할 질문이 있으면 **문의**.
3. 칭찬과 불만이 섞여 있으면 **불만**.
4. 별점과 본문이 어긋나면 본문을 따른다.

## 실행

백엔드를 실행한 상태에서 프로젝트 루트에서:

```bash
node eval/classify_eval.mjs
```

- 정확도는 **본문 있는 리뷰만** 계산한다 (평점만 리뷰는 규칙 처리라 항상 맞으므로 따로 확인).
- 유형별 정밀도·재현율, 혼동행렬, 틀린 리뷰 목록을 출력한다.
- 결과는 `eval/results/` 에 JSON 으로 저장된다. 프롬프트를 바꿀 때마다 돌려서 버전별로 비교한다.
- 목표: 85% 이상.
